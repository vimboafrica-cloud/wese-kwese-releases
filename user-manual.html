Wese~Kwese User Manual

Everything you need to run your school's fees on it, from installing it to closing a term.

Wese~Kwese is a fees system that runs on one computer in the school office — no internet connection needed day to day, no monthly subscription. Every other computer on the school network opens it in a web browser. Receipts, invoices, debtors and cash reports, fund tracking, and support for more than one currency (USD and ZiG side by side, or converted between them) are all built in.

This manual follows the same order as the app's own Getting started checklist on the Home page — work through it top to bottom the first time, then use the sidebar to jump straight to whatever you need later.

1Installing it

On the one PC in the office that will act as the server.

  1. Download the installer and double-click it on the PC that will be the server. This only needs doing once, on one computer.
  2. Windows shows "Windows protected your PC" — this is normal for a small independent app that isn't code-signed, not a virus warning. Click More info, then Run anyway.
  3. The wizard asks a few questions:
    QuestionWhat to answer
    Port8000 is fine unless something else on this PC already uses it.
    Time zoneAfrica/Harare.
    Backup folderA folder your cloud-sync app (e.g. MEGA) watches, so a copy leaves the building automatically every day.
    DatabaseBuilt-in (SQLite) — nothing else to install, fine for one school. Only choose PostgreSQL if you already run it.
    OptionsDesktop shortcut; allow other school PCs through the firewall (local network only); daily backup at 17:00.
  4. When it finishes, your browser opens on its own, on the first-run page. This only works on the server PC itself, and only once — it's where you create the very first Admin account. Choose a strong username and password.
  5. Other PCs on the school network open http://<server-PC-name>:8000/ in any browser.

Upgrading later

Run a newer Setup.exe over the top — it keeps your data and settings, and takes a backup first automatically. Never uninstall to upgrade.

2First-time setup

The Home page shows a Getting started checklist until every one of these is done.

1. School details

Menu → School details. Type the school's name exactly as it should appear on receipts, invoices, reports and exported files — this is the first thing every fresh install asks for. Address, phone and e-mail are optional and also print on documents.

2. The current term

Menu → Setup → Terms → Add term. Enter the year, the term number, and its opening and closing dates (used for part-term fee calculations later), then tick Is current — new invoices and payments default to whichever term is current.

3. Classes

Setup → Classes → Add class. Give each a name and a Sort order number — this controls the order classes are promoted in at the end of the year, so number them from youngest to oldest.

4. Fee categories and fee items

Fee categories group students who pay the same amount (Day Scholar, Boarder, Staff Child...). Fee items are what the fees are made of (Tuition, Levy, Building Fund...) — each item is also its own fund account that income and spending are tracked against, so keep the list to what you genuinely want to track separately. Both are under Setup.

5. Fee structures

Setup → Fee structures → Add fee structure. One structure per (fee category, term, currency) combination, listing how much each fee item costs. This is what generates every student's invoice — a category with no structure for the current term simply won't get invoiced.

6. A receipt book

Setup → Receipt books → Add receipt book. Just a number range, e.g. 1 to 999. Leave Method blank for one book used by every payment method (the normal case) — only set it if this school keeps a separate paper book per payment method.

7. The other people who'll use it

Menu → Users → Add a user. See Users & roles below for what each role can do.

8. Students

Add them one at a time, or use the Access importer if you're moving off the old system. See Adding & finding students.

3Adding & finding students

Adding a student

Students → Add student. The student number is generated automatically (two initials plus a running number, e.g. AM00001) and can never be typed in or changed — it's not on the form at all. Fill in class, fee category, and Bill fees in (which currency this student is invoiced in — see Multi-currency).

Finding a student

The Students list searches by name or student number, and filters by class or status. Every student's own page shows their full history: every invoice and payment they've ever had, all in one place.

Class lists

Students → Class list. One class, or every class one per printed page, with optional empty ruled columns for a register or mark sheet. Shows no money figures, so any signed-in staff member can print it.

4Fees & invoices

Generating invoices

Invoices → Generate term invoices. Pick a term and it creates an invoice for every active student who doesn't already have one — safe to run again later, existing invoices are left alone. A student is billed from whichever fee structure matches their fee category and their own currency; if none matches, they're listed as skipped so you can add the missing structure and run it again.

A single student's invoice can also be created on the spot from their own page, or from the payment screen if the term hasn't been billed for them yet.

Reducing fees (Admin only)

Open the invoice → Adjust fees. Covers a part-term fee for someone who left early, a bursary, a discount, a correction, or a debt written off. It can never reduce an invoice by more than what's still owing, needs a reason, and is recorded against who did it and when. Fee adjustments lists every one made; an Admin can void one to put the fees back exactly as they were. Only Admins can reduce fees, so the person collecting money is never the same person who can write debts off.

5Taking a payment

  1. Find the student and open their page (search by name or student number).
  2. Click Take payment.
  3. Pick which term's invoice this is towards — it shows what's still owing on each one.
  4. Type the amount, the date, and how it was paid (Cash, Bank, Ecocash, Telecash, Other).
  5. Click Record payment — you land straight on the official receipt, numbered automatically from the active receipt book.

A payment can never overpay an invoice

The amount is capped at what's still owing; the form tells you the limit as you type. Money is split across the invoice's fee items in proportion automatically (a $500 payment towards a $500 Tuition + $1,500 Levy invoice puts $125 towards Tuition and $375 towards Levy) — this is what feeds the fund balances in Spending.

Printing and downloading

Print sends the receipt straight to the browser's print dialog. Download offers PDF, Word, Excel or CSV — every receipt, invoice and report has the same button, and every file starts with the school's name, printed by whom, and when.

Voiding a payment

Nothing is ever deleted or edited once money has moved. Payments → (find it) → Void, type a reason — the record stays, struck through in lists and exports, with who voided it and why. If some of a receipt's money has already been spent from a fund, voiding is refused until that spending is voided first, so a fund can never go below zero.

6Reports

ReportAnswers
DebtorsWho still owes money, for a term — filter by class. Every row links straight to Take payment.
Daily cashHow much came in, and how, for any date range — split by payment method and by who received it. Run at the end of every day.
FundsWhat's actually in each fund right now — opening balance, income, spending, closing balance, per fee item.

All three, plus the Home page's own term summary tiles, download as PDF, Word, Excel or CSV. A school taking more than one currency sees each currency's figures as its own separate block on every report — see Multi-currency.

7Spending

Every fee item doubles as a fund: what's been received for it, less what's been spent from it. Spending → Record spending shows each fund's current balance right in the "Spend from fund" list, and you can only spend what a fund holds — an over-spend is refused with a message saying exactly how much is available.

Voiding a piece of spending puts the money back into the fund. Voiding a receipt whose money has already been spent is refused until that spending is voided first — a fund can never be pushed below zero.

8Other income

Money that isn't school fees — uniform sales, hall hire, that kind of thing. Other income → Record other income, choosing a category from a list rather than typing one, so the same thing is always spelled the same way in reports. No category yet? Click Add other income category right there on the form — nothing you've already typed is lost.

9When a student leaves

Nobody is ever deleted — their receipts have to stay on record. Open the student and click Record leaving instead.

  1. Choose the reason: transferred, completed school, withdrawn, stopped attending, expelled, passed away, entered by mistake or a duplicate, or other.
  2. Enter the date, and where they're going if that's useful (a transfer's new school name, say).
  3. If they still owe fees, the page tells you — but lets you record the leaving anyway.

They drop out of class lists, the active count, and new invoices, but anything still owing stays on the Debtors report until it's paid, marked with the reason. A printable student statement shows a receiving school exactly where the account stands — whether fees are cleared, and the leaving details.

Part-term fees, worked out automatically

For a student who left partway through a term whose dates are set (see First-time setup), the student's own page suggests a fair fee for the time actually attended, and offers to reduce the invoice by the rest in one click.

Bring back as an active student undoes a leaving completely — for someone entered by mistake, or who's coming back.

10End-of-year promotion

Students → End-of-year promotion. Moves every class up in one go: each class gets a suggested destination (the next class by the Sort order set under Setup → Classes, or the last class finishing school), you tick anyone repeating the year, review the whole plan, and confirm. Nothing changes until you confirm.

Students keep their full fee history, and past invoices keep the class they were actually billed in at the time — promoting a class never rewrites history. The latest promotion can be undone from the same page; anyone whose record has changed since is left as they are.

11Old records (Admin only)

Students → Old records. Sets how long former students' personal details (name, birth date, address, parents, phone, doctor, notes) are kept after they leave — default 7 years. Past that period, and only once a student owes nothing, an Admin can erase their personal details in bulk, or erase one student individually on request at any time.

Erasing replaces the name with "Former Student" but keeps the student number, every invoice and every receipt — reports and totals still add up correctly. It cannot be undone, and older backup files still hold the details as they were when each backup was made.

12Multi-currency

Most schools need only the one currency, already set up. A school that takes more than one (USD and ZiG, say) adds a row per currency under Setup → Currencies (code, symbol, and which one is the default), then sets up a fee structure in each currency for the same category and term, and gives every student a Bill fees in currency on their own record.

Currency mode

School details → Currency mode. Decides what happens when a payment doesn't match its invoice's currency — switchable at any time as the currency situation changes; switching never rewrites a payment already recorded.

ModeBehaviour
Strict (the default)A payment can only be in its invoice's own currency. Nothing is ever converted or added together — every report shows each currency as its own separate block.
BlendedAt the till, a payment can be received in a different currency and converted into the invoice's currency using an exchange rate. Reports still stay exactly as simple as Strict mode — they only ever see the already-converted figure, never a mix.

Using Blended mode

  1. Keep exchange rates current under Setup → Exchange rates — add a new row whenever the rate you're using changes (however you source it: bank, interbank, parallel market, it doesn't matter to the system).
  2. On the payment screen, tick Received in a different currency?, choose which currency, and type how much was actually handed over and the rate.
  3. The system converts it and applies the result to the bill. The receipt shows both figures — what was received, and what it became.

13Month end

Money menu → Month end. Closes a calendar month — once closed, nothing (a payment, spending, an adjustment) can be recorded or voided in it until an Admin reopens it. Use this once a month's books are settled, so nothing gets backdated into them by accident.

Users → Add a user. A new (or reset) password is temporary — the person must choose their own at first sign-in. Five wrong passwords in a row locks a username for 15 minutes; an Admin can unlock it sooner from the Users page.

Automatic sign-out: anyone who hasn't touched the screen for a while (3 minutes by default) gets a 30-second warning, then is signed out — Users → Sign-out timing to change it (1–60 minutes).

Forgot the only Admin's password? On the server PC: Start Menu → Wese~Kwese → Reset a forgotten Wese~Kwese password (needs Windows administrator permission). It lists every username, prints a one-time temporary password, and also clears a lockout.

15Backups

A backup runs automatically every day at 17:00 (the newest 30 are kept), and Backups → Back up now makes one on demand any time — worth doing right before something like an upgrade.

E-mailing a copy

Every backup can also e-mail itself to up to 5 addresses, as an AES-256 password-protected zip — the database holds every student and payment record, so nothing is e-mailed until a zip password of at least 8 characters is set. Write that password down somewhere safe: without it, the e-mailed backups can't be opened. Open one with the free 7-Zip.

Gmail (and most providers) need an "app password"

Your normal Gmail password won't work here — Google blocks it for apps like this. Instead:

  1. Turn on 2-Step Verification on the Google account you're sending from (Google Account → Security), if it isn't on already.
  2. Go to myaccount.google.com/apppasswords, name it (e.g. "Wese-Kwese Backups"), and create it — Google shows a 16-character password once.
  3. Paste that 16-character password into Mail account password on the Backups page — not your normal Gmail password.
  4. Make sure the Mail provider is set to Gmail (server smtp.gmail.com, port 587, security STARTTLS) — the wrong port/security combination shows a "mail server hung up" error.
  5. Double-check the app password was created under the same Google account entered as the username — an app password only works for the account it was made under.

Click Save, then Send a test e-mail to confirm it went through.

If the e-mail can't go out for any reason, the copy on this PC is still made regardless, and the reason is shown on the Backups page and as a warning on the Admin's Home page.

16Restoring a backup

On the server PC: Start Menu → Wese~Kwese → Restore a Wese~Kwese backup (needs Windows administrator permission, since it's about to replace the live data — not done from inside the app itself).

  1. It lists the backups on this PC, or takes the path of a backup file (or an e-mailed zip, plus its password).
  2. Shows what's in the backup next to what Wese~Kwese holds now, and warns about anything that would be lost.
  3. Nothing happens until you type RESTORE.
  4. It saves a safety copy of the current data first (never overwritten), swaps the backup in, upgrades it if it came from an older version, and restarts the server.

Practise this once, on a quiet day

So you're not learning it for the first time during a real emergency. To undo a restore, restore the safety copy it saved automatically before making the swap.

17Bringing over old Access data

Start Menu → Wese~Kwese → Import old Access data into Wese~Kwese — needs the free Microsoft Access Database Engine (64-bit), and only works while Wese~Kwese is still completely empty. It does a practice run first, shows every warning, and only actually imports once you type YES. Each imported user gets a one-time temporary password, printed once — write them down. It also checks its totals against the old database's own Income and CurrentAcc tables and prints any difference, so you can verify nothing was lost in translation.

The old Access database has no idea of multiple currencies, so everything is imported into the school's one default currency — add more under Setup → Currencies afterwards if needed.

18Troubleshooting

"Windows protected your PC" when running the installer

Expected — the installer isn't code-signed yet. Click More info, then Run anyway. Not a sign of a virus.

Backup e-mail fails: "server refused the username or password"

You're using a normal Gmail password instead of an app password — see Backups above for the full fix.

Backup e-mail fails: "mail server hung up"

Port and security type don't match. For Gmail: server smtp.gmail.com, port 587, security STARTTLS.

Another PC says "That address isn't allowed"

Open C:\ProgramData\SchoolFees\.env as administrator on the server PC, add the new address to ALLOWED_HOSTS, save, then use Restart the Wese~Kwese server from the Start Menu. A fixed IP address for the server PC (set in your router) avoids this happening again.

Can't sign in / locked out

An Admin resets it under Users. A username locks for 15 minutes after 5 wrong passwords in a row — an Admin can clear that sooner. If the only Admin is locked out or has forgotten their password, use the Start Menu → Reset a forgotten Wese~Kwese password tool on the server PC.

A student's fee category changed mid-term

Not automatic — changing a student's fee category or class partway through a term doesn't re-bill an invoice already generated. Use Adjust fees on the invoice to correct the amount, with a note explaining why.
